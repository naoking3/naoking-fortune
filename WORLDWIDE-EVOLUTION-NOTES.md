# NAOKING KINGDOM — WORLDWIDE EVOLUTION NOTES

Implementation selection after the repository audit, worldwide creative research, retention/sound research, and page-by-page evolution audit.

## Selection rules

Every selected system must score well on:

- Impact: a visitor can feel it without reading an implementation note.
- Originality: it belongs to NAOKING KINGDOM rather than a generic component gallery.
- Return motivation: it changes, remembers, or reveals without punishing absence.
- Safety: Oracle outcome probabilities and the established roulette controller stay untouched.
- Mobile: the same concept survives with fewer layers and shorter motion.
- Maintenance: one registry/data source owns each kind of state.

No new third-party runtime is required for this pass. Existing DOM, CSS, Canvas and the shared Web Audio engine are enough, so the initial route does not pay a framework or WebGL tax.

## Architecture selected

```text
local calendar
  -> immutable Daily Kingdom Context
      -> world state / tide / decree / relic / photo motif / errands
      -> body tokens and background response
      -> district-specific ambient profile
      -> optional, presentation-only encounter

navigation
  -> district registry
      -> page identity / transition grammar / sound identity
      -> browser-local visit and discovery record

26-photo catalog
  -> rotating background
  -> home snapshot
  -> gallery image, caption, focal point and tone
```

The Oracle remains a separate authority. Daily state and surprises may alter presentation atmosphere only; they never read, write, re-roll, weight, or label the committed fortune result.

## Systems selected for implementation

1. **Daily Kingdom Context** — one deterministic record owns the date, world state, decree, tide, relic, photo motif and three optional errands.
2. **District Registry** — page depth, accent, transition, sound and signature metadata live in one extensible map.
3. **Living Background Contract** — daily state, time phase, page and current photo expose CSS tokens; the photo remains intact below them.
4. **Kingdom Logbook** — local-only visit days, visited districts, photo discoveries, favorites and secrets. No streak loss and no competitive score.
5. **Site-wide Encounter Registry** — one medium-frequency non-blocking encounter per session at most, with reduced-motion and Page Visibility gates.
6. **NAOKING Background Actor** — uses an existing owned character asset in the non-content perimeter; never covers controls.
7. **District Transitions** — the established water transition keeps its timing and lifecycle while destination-specific masks/flavors change.
8. **District Sound Profiles** — all remain inside the existing single AudioContext and route lifecycle.
9. **Photo Catalog** — the exact 26 images become one immutable metadata source for background and gallery.
10. **Hidden Discoveries** — missing archive record, decree seal, gallery favorite and a background encounter; all are optional and resettable.

## Return and discovery policy

- Absence never destroys a collection, breaks a streak, or removes content.
- A visit day is recorded once; older days are capped.
- Daily errands are optional prompts to explore existing features, not chores required for access.
- Discoveries unlock logbook copy and small visual marks only.
- All history is browser-local, versioned, safely parsed, capped, clearable, and not transmitted.
- A new day changes the kingdom context. A new session may change one small encounter without altering the daily state.

## Surprise policy

- Medium encounter: at most once per session, after the page is usable.
- Rare encounter: deterministic eligibility plus a cooldown; never below a critical control.
- Disabled when the document is hidden, reduced motion is requested, or a full Oracle/game scene is active.
- Any input or page change cancels and cleans up a running decorative encounter.
- Surprise selection is independent of all fortune results.

## Asset plan

- Reuse the owned NAOKING character and the 26 owned/compressed background photos.
- Create district ornaments, currents, seals, bubbles, projector marks and portal apertures procedurally with HTML/CSS/SVG-like CSS shapes.
- Add no external sound file in this pass; procedural sound avoids provenance and payload costs.
- Add no third-party library in this pass. Research records remain available for a later optional scene once the lifecycle warrants it.

## Quality budgets

- No new always-running canvas or animation loop.
- One decorative encounter timer, canceled on route/visibility/input.
- Transform/opacity/clip-path only for transitions; reduced-motion resolves immediately.
- Mobile removes secondary actor layers, expensive filters and long paths while retaining the district palette and signature symbol.
- Background photos stay lazy/preloaded one at a time and remain the same 26 WebP files.
- New browser-local arrays have hard caps and no unbounded history.

## Five polish passes to run after implementation

1. Creative art direction — every district identifiable without reading its heading.
2. Motion/interaction — entrances feel different, focus and skip paths remain immediate.
3. Retention/game design — daily changes are visible, optional and non-punitive.
4. Sound design — page profiles are distinct at low volume and fully silent when off.
5. Character/comedy — beauty stays primary, with brief unmistakably NAOKING absurdity.

Then run frontend, mobile, accessibility, cleanup, performance and Git preservation checks.
